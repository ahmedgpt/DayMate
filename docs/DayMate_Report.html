DayMate: AI Daily Diary & Reminder Assistant

A Telegram assistant that logs your day, sets reminders and writes summaries. An LLM agent works through tools on a Python MCP server, and n8n runs the scheduled automation.

Python 3.12MCP (FastMCP, streamable HTTP)Groq · gpt-oss-120bSQLiten8n 2.45 in DockerTelegram Bot API

Purpose

People forget to record what they did and lose track of small deadlines. DayMate keeps both in one chat: you type what you did or what you need to remember, and the assistant stores it, reminds you on time and summarises your day or week from what was actually recorded.

For the assignment it demonstrates an MCP server whose tools are called by an AI agent, a real external API (Open-Meteo weather) and a working n8n agent workflow.

Scope

In scope

  • Diary: add, view by date or range, update entries
  • Reminders: create, list, cancel, delivered on time
  • Daily and weekly summaries built from stored entries
  • Weather: current, 15-day forecast, historical
  • Per-user timezone and per-user data isolation

Out of scope

  • Web or mobile dashboard
  • Calendar sync, voice or image input
  • Recurring reminders
  • Long-term semantic memory or RAG
  • Cloud hosting (runs locally)

Architecture

One Python server is the single source of truth. The agent reaches it over MCP, and n8n reaches it over a small REST API on the same port. Neither the model nor n8n touches the database directly.

Components and trust boundaries. n8n never calls Telegram itself; the server sends every message.

How a chat message works

sequenceDiagram
  participant U as User
  participant B as Bot
  participant A as Agent
  participant L as Groq LLM
  participant M as MCP server
  participant D as SQLite
  U->>B: "Remind me tomorrow at 10 AM to submit my assignment"
  B->>A: text + internal user id
  A->>L: prompt (local time, timezone) + tool list
  L-->>A: call create_reminder(message, scheduled_at)
  A->>M: MCP call · headers: token, X-DayMate-User-Id
  M->>D: validate, convert to UTC, insert
  M-->>A: success: Tue 10:00 (Asia/Karachi)
  A->>L: tool result
  L-->>A: final reply
  A-->>U: "Your reminder is set for Tue 10:00 (Asia/Karachi)"

The model chooses the tool and its arguments. The user's identity comes from the bot, never from the model.

How reminders are delivered

n8n is the only scheduler. Every minute it leases the reminders that are due, then asks the server to deliver each one. The server sends the Telegram message and records the result, so a reminder is marked sent only after Telegram confirms it.

sequenceDiagram
  participant N as n8n (every minute)
  participant S as DayMate server
  participant D as SQLite
  participant T as Telegram
  N->>S: POST /api/reminders/claim-due
  S->>D: lease due pending reminders (5 min)
  S-->>N: leased reminders
  loop each reminder
    N->>S: POST /api/reminders/{id}/deliver
    S->>T: sendMessage
    alt Telegram confirms
      S->>D: status = sent
      S-->>N: 200 · Delivered
    else send fails
      S->>D: release lease, record error, attempt + 1
      S-->>N: 502 · will retry (failed after 5 attempts)
    end
  end
  • No duplicates: a leased reminder is invisible to overlapping runs. A repeated delivery call finds it already sent and sends nothing.
  • Retries: failures stay pending and are retried up to 5 times, then become failed.
  • Why the server sends: Telegram is unreliable from inside Docker on this network, and n8n then needs no Telegram credential.

The daily (23:00) and weekly (Sunday 20:00) workflows ask the server which users are due in their own timezone. An n8n AI Agent node with the Groq model writes the summary from the returned entries, and the server sends it.

Design rules

  • Identity: no tool accepts a user_id. Our code sets the user in a request header, so the model cannot read or change another user's data.
  • Truthfulness: the agent confirms an action only after the tool reports success. Summary counts and totals are computed in code, and the LLM writes only the prose.
  • Time: reminders are stored in UTC with the user's timezone and shown in local time. Vague times such as "tomorrow morning" make the agent ask for an exact time.
  • Secrets: keys live in .env and in n8n's encrypted credential store. The API listens on localhost behind a bearer token.

Running it

Prerequisites: Docker Desktop running and .env filled in (GROQ_API_KEY, TELEGRAM_BOT_TOKEN, MCP_AUTH_TOKEN).

D:\DayMate\start_daymate.bat     # starts n8n, the server and the Telegram bot
D:\DayMate\stop_daymate.bat      # stops everything; data is kept

Then message @DayMate_aiBot on Telegram. n8n runs at http://localhost:5678.
